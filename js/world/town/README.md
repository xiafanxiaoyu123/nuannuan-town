# Town 场景模块

对外入口仍是 `../town.js` 中的 `Town` 类和原坐标导出。入口持有所有既有实例字段，明确编排构造、生命周期和每帧调用；这里的具名函数接收同一个 `town` 实例，不动态安装原型，也不维护第二份状态。

| 文件 | 修改职责 |
| --- | --- |
| `layout.js` | 岛、房间、门、道路的坐标，以及圆角岛距离计算 |
| `scenery.js` | 主岛与街区模型、场景放置/标记、静态合批 |
| `housing.js` | 后院、外部房屋、室内与院界的构建、扩建、重建和资源释放 |
| `environment.js` | 灯光、天空、昼夜时钟、云/蝴蝶/店铺等氛围动画 |
| `navigation.js` | 区域切换、碰撞边界、射线落点、建造岛高度和楼梯移动 |
| `input.js` | 键鼠/触屏监听、输入屏蔽、交互候选和提示更新 |
| `residents.js` | 玩家/居民初建、居民交流奖励、委托标记和散步 |
| `player.js` | 人物与大喵移动、姿势、换装、跟随与自动浇水 |
| `camera.js` | 标题/游玩/装修相机、楼层屋顶可见性、后处理 |

## 必须保留的不变量

- `RLOT`、`RC`、`DOORS` 是共享对象。房屋扩建原位更新；不要重新赋值、深复制或改成每次计算返回新对象。旧 `town.js` 导出和装修系统持有同一引用。
- 构造调用及随机调用顺序决定场景、居民位置和动画初始状态。入口构造器保留这份顺序，组件不能在导入时创建 Town 或订阅输入。
- 每帧顺序为：昼夜 → 玩家/大喵 → 居民 → 农场 → 当区装修 → 建筑截面 → 场景 ticks → 交互提示 → 镜头 → 氛围/季节 → 后处理。拆分不是改变玩法、时钟或帧调度的授权。
- 旧字段和方法仍可能被装修、拍照、节日或家居互动直接使用。新增内部函数可以显式委托；不要删除兼容入口或另存角色/碰撞状态。
- 房间、院界重建要沿用原来的季节登记清理、场景移除、独占资源释放、碰撞和标记移除顺序；共享几何/材质交给既有资源工具处理。
- `input.js` 保留原 Town 生命周期的输入订阅方式；不要在每次进出区域或每帧重复调用 `bindInput()`。
- 全局水面是固定 900×900 模型，显式标为 `renderGlobal`。不要把所有空包围盒或动态对象都缓存为全局，否则后续新增模型可能错误地跳过剔除。
- `../scene-performance.js` 只复用本次同步绘制的工作缓冲；嵌套绘制按深度隔离，异常也要恢复原 `scene.children`。家具资格仍逐帧检查，不以 revision 代替缩放、显隐与动画检查。用 `npm run qa:scene` 验证这些约束。

## 验证

从工程根执行 `node tools/qa/town_module_checks.cjs`，使用内存存档和真实 Three/模型/农场/装修/季节代码验证当前行为。需要旧实现对照时，设置 `TOWN_BASELINE` 为已审核的 `before` 目录；测试只把旧 `town.js` 与当前 Town 对比，两边依赖使用同一份当前代码。可用 `TOWN_QA_OUT` 指定本次报告目录。

真实交互使用 Electron 执行 `tools/qa/town_module_ui_checks.js`，沿用 `live_harness.js` 的独立 profile、slot 和外网拦截。先按维护规范启动隔离开发服务，并将 `LIVE_QA_OUT` 指向本轮新目录。该检查覆盖键盘/触屏、门口转场、重建释放与保存重载；不代表 APK、物理设备或线上验收。
