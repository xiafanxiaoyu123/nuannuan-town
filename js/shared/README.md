# 共享数据

这里保存跨系统共用的内容定义和新档默认值。修改物品价格、任务奖励、初始资产时先查此处。

| 文件 | 负责内容 |
| --- | --- |
| `player-defaults.js` | 玩家新档默认字段、独立对象工厂、旧档迁移共用的初始田地 |
| `clothing.js` | 风格、服装、默认搭配、套装；详细高星套装造型仍引用 `../premium-outfits.js` |
| `farming.js` | 作物、果树定义与索引 |
| `furniture.js` | 家具、地板、房屋等级、美化度等级；巨大作物摆件依赖 farming |
| `shops.js` | 店铺和升级档位 |
| `progression.js` | 主线任务、教程、成就 |
| `residents.js` | 居民、居民家、委托 |
| `world.js` | 后院升级规格 |
| `daily.js` | 每日订单、宝箱及进度字段契约 |
| `calendar.js` | 显式传入镇历天数的纯日期计算；当前玩家日期仍从 core/gametime.js 读取 |
| `effect-rules.js` | 服装套装与节日加成纯计算；依赖内容表，不读取玩家状态 |

`js/data.js` 是旧路径的兼容导出，`js/live/data.js` 继续导出每日定义。它们转出同一对象，没有维护第二份数据。新代码优先直接引用对应文件，避免把整个内容目录当作依赖入口。

运行中的玩家进度仍由 `js/core/state.js` 的 `S` 管理；不要在这里创建第二个玩家单例，或把保存、奖励、UI、网络调用塞进定义文件。`createPlayerDefaults()` 每次返回独立对象；正式与试玩的隔离仍由现有 state/local-play 模块完成。

保留既有的内容扩展方式，例如面包房安装时扩充 SHOPS，因此没有冻结所有定义对象。若要改成不可变数据，需要同时迁移这些扩展点。

物品 ID 是存档与后台礼包目录的契约。删改 ID、发放资格或存档字段时须检查旧档迁移及后台目录。目录搬迁本身不应改变价格、奖励、抽单顺序或默认资产。
