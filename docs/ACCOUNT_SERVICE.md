# 账号服务与存档契约

本仓库的账号服务、后台工作台及纯数据校验共享当前游戏存档契约。需要 Node.js 24 或更高版本；根目录保留 CommonJS 服务端与浏览器 ES Module 的原有组织方式。

## 本地验证

```sh
npm ci
npm run check
npm test
npm run qa:backend
```

`qa:backend` 通过 `safe_local.py` 执行 16 套回归。入口只继承操作系统必要变量，测试使用合成账号、内存或临时数据库，支付请求使用拦截夹具。不要绕过安全入口直接继承真实 `AUTH_DB`、管理员或支付配置。`AUTH_DB` 优先于 `DATA_DIR`，仅更换后者不代表已隔离。脚本不是操作系统沙箱。

运行本地游戏可用 `npm run dev`，安全入口会使用独立测试数据目录、回环监听地址并关闭支付。`npm start` / `npm run start:api` 则是自行部署入口，会使用显式配置或默认 `data/`；首次启动前先确认自己的数据目录。

## 自行部署

- 设置明确的 `APP_ORIGINS`，每项必须是无路径、无末尾斜线的精确 Origin，不支持通配符。生产模式或 `COOKIE_SECURE=1` 时，漏配不会自动允许任意跨域网站。
- 本机 HTTP 开发可使用 `.env.example` 的两个回环 Origin。自行配置 Android API 时，按实际宿主增加 `https://localhost` 等精确来源；它不是任意子域通配。Windows 同源 API 代理不要求放开任意网页来源。
- `TRUST_PROXY` 默认空，不信任转发请求头。只填写实际反向代理的 IP/CIDR，或同机代理使用 `loopback`；不支持全网信任。多级代理从右向左确定首个不可信来源。
- 最外层代理应覆盖客户端提交的来源头。只有一个 Nginx 入口时可使用 `proxy_set_header X-Forwarded-For $remote_addr;`，再将 API 的 `TRUST_PROXY` 设置为该入口的实际地址范围。不要把客户端自行提供的头当作访问者真实地址。
- 配置自己的 `ADMIN_PUBLIC_ORIGIN` 和随机管理员令牌，HTTPS 部署使用安全 Cookie。管理员令牌不写进网页、仓库、日志或截图。
- 保持 `PAYMENT_CHECKOUT_ENABLED=0`、`PORTAL_COMMERCE_READY=0`；支付不会因复制示例而开通。测试内的合成商户、密码、生成密钥和非法 URL 仅用于测试，不是可用商户资料。

## 兼容与写入保护

花肥统一保存在 `stats.fertilizer`。历史 `seeds.fertilizer` 与现有数量合并后移除旧键，重复加载或同步不会重复增加；领取标记不重置。画框兼容主题字符串和历史数字 0–20，保留主题、家具位置与装修方案。旧周常保留能确认的进度和领取状态，无法还原的创建基线不会倒算成完整本周次数。

服务端直接使用 `server/save-contract.js` 与游戏共享的纯数据校验，错误存档不会替换有效云档。正常同步、直接礼包和单封邮件领取的新请求携带非负安全整数 `baseRevision`；陈旧版本拒绝并返回冲突。已成功请求的幂等重试继续返回原结果，不能因重试重复发放。数量溢出整笔回滚，不截低玩家合法余额。

微信适配器的响应断流、成功验签与退款待核对分支由离线夹具验证。退款状态不被直接视作全部退款完成，也不会自动撤销玩家权益。真实支付需要部署者独立配置与验收，本仓库默认关闭。

## 证据边界

源码、隔离回归、浏览器、原生包构建、设备安装和线上服务是不同验收层级。更新仓库不代表已部署 API，也不会自动修改已有服务器配置或玩家数据库。自行发布时备份自己的数据库，分别验证旧档导入、导出、重载、首次本地/云端选择、版本冲突和重复请求。
